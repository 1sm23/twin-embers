## 差异

逐项执行上游 6,734 项重建配方，并比较资源大小和 CRC：

- 6,675 项与原美版配方匹配。
- 59 项 CRC 改变，重建操作本身均未越界或报错。
- 40 项是游戏数据区：事件脚本、对话、战斗文字、名字、物品和招式描述等。
- 19 项是图形区：4 个拉丁字体资源、命名界面、标题、菜单等。

这个统计只覆盖上游配方提取的资源。它没有覆盖整个 ROM 的 GBA 可执行代码或所有
新增区，不能据此认定只有 59 处改动。

## 为什么加一个哈希不够

Twin Embers 编译 `pret/pokefirered` 的 C 代码运行在 3DS ARM11 上，不执行汉化 ROM
中的 GBA ARM7/Thumb 代码。汉化的多字节文字解码、字形绘制和字宽逻辑必须移植到
这个原生引擎，下屏的文字转换与渲染也需要处理中文。

此外，当前 REX 加载器会按美版编译时的指针表覆盖资源中的地址。若汉化移动了文本
或修改了指针，直接套用美版地址会读错内容。资源 CRC、引擎 ABI 和存档中的名字
处理也必须保持一致。仅跳过 SHA-1/CRC 或改区域标识不会解决这些问题。

## 完成原生中文移植还需要

1. 确认这份汉化的文本编码、字库位置／格式，以及被替换的文字处理函数。
2. 建立重定位后的中文文本与原生符号对应关系；生成独立的结构化重建配方。
3. 移植主游戏和下屏的解码、字形、字宽、截断、名字与占位符处理。
4. 构建与配方一致的独立引擎 ABI；保留美版支持及严格版本识别。
5. 在模拟器和实机验证新游戏、命名、对话、战斗、物品／招式、存档和读档。

若能取得该版本汉化补丁的源码、编码表或作者的技术说明，能直接核对这些机制；
否则需要对所提供 ROM 的汉化代码继续逆向分析。目前尚未完成这些工作，不能标为可玩。

## 本地复现诊断

```powershell
python -m pip install ./builder
firered3ds-builder inspect-rom "C:\Games\火红.gba" --compare
```

输出只包含大小、哈希、版本判断、资源路径及计数，不输出游戏资源内容。
`native_supported: false` 表示目前不能作为原生 Builder 的输入；识别并不等于兼容。
FTP 安装的使用方法见 [FTP-INSTALL.md](FTP-INSTALL.md)。
